# 1. Общие положения
   
Настоящая инструкция предназначена для специалистов, которые внедряют доработанную конфигурацию в рабочую информационную базу (ИБ), где уже ведётся реальный учёт.

Внимание! Перед выполнением любых действий обязательно создайте резервную копию рабочей базы.

Доработанный функционал включает:
Ведение договоров абонентского обслуживания.
Оформление заявок (документ «Обслуживание клиента») с учётом выполненных работ.
Расчёт управленческой зарплаты (оклады, проценты от выработки, премии, НДФЛ, взаиморасчёты).
Планирование отпусков и контроль графика (диаграмма Ганта).
Автоматическое формирование актов (реализация товаров и услуг) по абонентским договорам.
Массовое создание актов за месяц.
Telegram-оповещение специалистов о новых заявках.
Управленческие отчёты.

Для корректной работы нового функционала необходимо выполнить описанные ниже шаги в указанном порядке.

## 2. Заполнение системных констант
   
Для корректной работы новых подсистем необходимо задать значения нескольких констант. Все они находятся в разделе «Добавленные объекты → Сервис» (также их можно найти через глобальный поиск).
Перечислим их по порядку:

2.1. Номенклатура абонентская плата. Здесь указывается элемент справочника «Номенклатура», который будет автоматически подставляться в документы реализации при формировании строки с абонентской платой. Рекомендуется создать отдельный вид номенклатуры, например, «Абонентское обслуживание (мес.)», чтобы отличать его от прочих услуг.

2.2. Номенклатура работы специалиста. Аналогично, это ссылка на номенклатуру, которая используется для отражения фактических работ специалиста в актах. Обычно создают позицию с наименованием «Работы специалиста (час)», чтобы в акте было понятно, что это почасовая оплата.

2.3. Токен управления телеграм-ботом. Этот токен необходим, если вы планируете использовать оповещения специалистов через Telegram. Токен выдаётся при создании бота – обратитесь к официальному боту @BotFather и следуйте его инструкциям. Полученную строку вида 1234567890:ABCdefGHIjklMNOpqrsTUVwxyz скопируйте в константу.

2.4. Идентификатор группы для оповещения. Сюда вставляется числовой идентификатор чата или группы, куда бот будет присылать уведомления о новых и изменённых заявках. Узнать ID можно, например, с помощью бота @userinfobot – достаточно отправить ему любое сообщение из нужной группы, и он вернёт его идентификатор. Обратите внимание: для групп идентификатор обычно начинается с минуса, например, -123456789.

# ВАЖНО: Если Telegram-оповещения не планируются, константы можно оставить пустыми — остальной функционал будет работать без ошибок. Однако перед запуском обязательно заполните две первые константы (номенклатура), иначе автозаполнение актов не сработает.

## 3. Настройка нормативно-справочной информации (НСИ)
3.1. Договоры с клиентами (абонентское обслуживание)
Для каждого контрагента, с которым заключён договор абонентского обслуживания:
Откройте раздел «Добавленные объекты» → «Обслуживание клиента» → «Договоры контрагентов» (или найдите через поиск "Договоры контрагентов")

Выберите нужный договор или создайте новый.
В поле «Вид договора» установите значение Абонентское обслуживание.
После этого станут доступны дополнительные реквизиты — заполните их:
Дата начала действия — первый день обслуживания.
Дата окончания действия — последний день обслуживания.
Сумма абонентской платы — ежемесячный фиксированный платёж.
Стоимость часа работы специалиста — ставка, по которой клиенту выставляются фактические работы.

Если договоры уже существовали, но им не был присвоен новый вид, отредактируйте их вручную — автоматического переноса данных нет!

3.2. Условия оплаты сотрудников (для расчёта зарплаты)
Регистр сведений «Условия оплаты сотрудников» хранит для каждого сотрудника:
Оклад (месячный, для всех категорий).
Процент от выполненных работ (только для специалистов).
Как заполнить:
Перейдите в раздел «Добавленные объекты» → «Зарплата» → «Условия оплаты сотрудников».
Для каждого сотрудника создайте запись с периодом, с которого начинают действовать условия (обычно первое число текущего месяца):
Сотрудник — выберите из справочника пользователей.
Период — дата начала действия условий.
Оклад — сумма (например, 50 000).
Процент от работ — для специалистов укажите числом (например, 15 означает 15%). Для административного персонала оставьте 0

Если в будущем оклад или процент изменятся, добавьте новую запись с более поздней датой периода — система будет использовать актуальное значение на дату расчёта.

# ВАЖНО: Если на дату документа «Обслуживание клиента» у специалиста вообще не заполнен процент (пустое значение), то документ не проведётся (это защита от ошибок). Если процент равен 0 — проведение разрешено.

3.3. Графики работы (для расчёта оклада пропорционально времени)
Для корректного расчёта заработной платы необходимо заполнить графики работы.
Откройте раздел «Добавленные объекты» → «Зарплата» → «Графики работы» (или найдите через поиск "Графики работы")
Создайте график работы (например, "Пятидневный")
Откройте обработку «Заполнение графика» (находится в разделе «Добавленные объекты» → «Сервис»).
Выберите график работы (например, «Пятидневка»).
Укажите период, на который создаётся график (обычно на весь год).
В поле «Выходные дни» укажите номера дней недели через запятую (где 1 — понедельник, 7 — воскресенье), например 6, 7 для стандартных выходных.
Нажмите кнопку «Заполнить» — обработка автоматически создаст записи в регистре сведений «Графики работы».

# ВАЖНО! Если у вас несколько графиков (например, для разных отделов), повторите процедуру для каждого.

## 4. Назначение прав доступа
Для работы с новыми объектами необходимо добавить пользователям соответствующие роли. В конфигурацию уже встроены профили групп доступа — это самый удобный способ.

4.1. Доступные профили
Специалист	- Добавление и изменение обслуживание клиента, чтение отчета по выработке специалистов.
Менеджер	- Добавление и изменение обслуживание клиента.
БухгалтерИТФирмы	- Добавление и изменение обслуживание клиента, массовое создание актов реализации, чтение отчета по анализу выставленных актов.	
КадровикРасчетчик	- Расчет зарплаты, планирование отпусков, чтение отчета по выработке специалистов, чтение отчета по зарплате и отпускам	Кадровики.

4.2. Как назначить
Зайдите в раздел «Администрирование» → «Настройки пользователей и прав» → «Пользователи».

Откройте карточку нужного пользователя или создайте нового.
Перейдите на вкладку «Права доступа».
Отметьте необходимые профили галочкой.
Если пользователь совмещает должности, можно добавить несколько профилей.
Рекомендуется использовать именно профили — это упрощает дальнейшее администрирование и соответствует типовым должностям.

## 5. Настройка Telegram-бота и регламентного задания
5.1. Проверьте константы (см. раздел 2)
Убедитесь, что заполнены «Токен управления телеграм» и «Идентификатор группы для оповещения».

5.2. Настройте регламентное задание
Регламентное задание «Отправка уведомлений Telegram-ботом» отвечает за отправку сообщений о новых/изменённых заявках (Обслуживание клиентов).

Перейдите в «Администрирование» → «Обслуживание» → «Регламентные и фоновые задания».
Найдите задание с наименованием "Уведомления телеграм боту".
Перейдите на вкладку "Расписание" и установите расписание, например, каждые 1–2 минуты.

# ВАЖНО! Убедитесь, что флаг «Включено» активен.

Если Telegram-бот не используется, задание можно оставить выключенным — это не вызовет ошибок.

## 6. Проверка работоспособности (ключевые сценарии)
После выполнения всех настроек рекомендуется проверить основные бизнес-процессы.

6.1. Создание и проведение заявки (Обслуживание клиента)
Перейдите в «Обслуживание клиентов» → «Обслуживание клиентов».
Создайте документ «Обслуживание клиента».
Выберите клиента и договор с видом «Абонентское обслуживание».
Укажите специалиста, дату, плановое время начала/окончания, описание проблемы.
Запишите документ. При первой записи (или при изменении даты/специалиста) в справочник «Уведомления телеграм боту» добавляется сообщение, и регламентное задание отправит его в Telegram.
Проведите документ. Проверьте движения:
В регистре «Выполненные клиенту работы» — по клиенту, договору, с суммой = часы × ставка часа из договора.
В регистре «Выполненные сотрудником работы» — по сотруднику, с суммой = часы × ставка часа × процент специалиста / 100.

6.2. Расчёт зарплаты
Перейдите в «Добавленные обьекты» → «Зарплата» → «Начисление заработной платы».
Создайте документ «Начисление заработной платы» за месяц, в котором были выполненные работы.
Заполните его (Сотрудник, график работы (например - "Пятидневный), вид расчета (например - "Оклад", или "Отпуск"), дату начала и дату окончания). Система рассчитает:
Оклад (пропорционально отработанному времени согласно графику).
Процент от работ (на основании регистра «Выполненные сотрудником работы» за месяц).

Проведите документ. Должны сформироваться движения по регистрам расчёта и взаиморасчётов, а также удержание НДФЛ.

6.3. Формирование акта (Реализация товаров и услуг)
Перейдите в «Обслуживание клиентов» → «Реализация товаров и услуг».
Создайте документ «Реализация товаров и услуг», выберите организацию, контрагента и договор абонентского обслуживания.
Нажмите команду «Заполнить».
Если в договоре указана абонентская плата > 0, добавится строка с номенклатурой из константы.
Если за месяц документа есть записи в регистре «Выполненные клиенту работы» по этому договору, добавится строка с работами специалиста.
Проведите документ и проверьте печатную форму «Акт об оказанных услугах» (должны быть все подписи, суммы прописью и т.д.).

6.4. Массовое создание актов
Откройте обработку «Массовое создание актов» (раздел «Добавленные объекты» → «Сервис»).
Укажите месяц, нажмите «Заполнить акты».
Обработка найдёт все абонентские договоры, по которым ещё нет реализации за этот месяц, и создаст (проведёт) документы «Реализация товаров и услуг» с автозаполнением.

6.5. Отчёты
Проверьте формирование всех отчётов:
«Выработка специалистов» — часы и начисленный процент по сотруднику за период.
«Анализ выставленных актов» — что должно быть выставлено клиентам против того, что фактически выставлено.
«Расчёты с сотрудниками» — начисления, выплаты, задолженность на начало и конец периода.
«Расход запланированных отпусков» — плановые и фактические дни отпуска.

## 7. Возможные проблемы и способы их решения
В ходе работы с новым функционалом могут возникать типичные ошибки. Ниже приведены наиболее частые ситуации и рекомендации по их устранению.

7.1. Документ «Обслуживание клиента» не проводится.
Наиболее вероятная причина — для выбранного специалиста на дату документа отсутствует запись в регистре сведений «Условия оплаты сотрудников», а именно не указан процент от выполненных работ. Система требует, чтобы этот процент был определён (даже если он равен нулю). Чтобы исправить ситуацию, зайдите в регистр и создайте запись для этого сотрудника с указанием периода (дата документа должна попадать в интервал действия записи) и нужного значения процента.

7.2. При автозаполнении документа «Реализация товаров и услуг» не добавляются строки.
Причин может быть две. Первая — не заполнены системные константы «Номенклатура абонентская плата» или «Номенклатура работы специалиста». Вторая — в регистре накопления «Выполненные клиенту работы» отсутствуют записи за месяц, на который приходится дата документа. Проверьте обе константы, а затем убедитесь, что за нужный месяц были проведены документы «Обслуживание клиента» по соответствующему договору.

7.3. Telegram-уведомления не приходят.
Это может быть связано с неверно указанным токеном бота или идентификатором группы, отключённым регламентным заданием «Отправка уведомлений Telegram-ботом», либо отсутствием интернет-соединения на сервере 1С. Проверьте корректность констант, убедитесь, что регламентное задание включено и работает по расписанию, а также что сервер имеет доступ к внешней сети.

7.4. При расчёте заработной платы не учитываются выполненные специалистом работы.
Обычно это происходит, если документы «Обслуживание клиента» не были проведены, либо их дата не попадает в месяц, за который производится начисление. Проверьте, что все необходимые заявки проведены и их даты соответствуют расчётному периоду. Также убедитесь, что в регистре «Выполненные сотрудником работы» есть движения за этот месяц.

7.5. Отпускные рассчитываются как нулевые.
Алгоритм расчёта отпускных использует сумму начислений за предыдущие 12 календарных месяцев. Если база только внедрена и истории начислений нет, либо она неполная, то отпускные будут равны нулю. В этом случае необходимо ввести начальные остатки по начислениям  или дождаться накопления данных за год. Для новых сотрудников также можно ввести расчётные суммы вручную.

7.6. Оклад начисляется не пропорционально отработанному времени.
Для корректного пропорционального расчёта оклада (например, при приёме/увольнении в середине месяца или при больничных) системе необходимы данные о графиках работы сотрудников. Если графики не заполнены на нужный месяц, расчёт будет выполняться исходя из полного месяца, что неверно. Заполните графики работы, используя обработку «Заполнение графика» (см. раздел 3.3 настоящей инструкции), и перепроведите документы начисления зарплаты.

## 8. Рекомендации по эксплуатации
Ежемесячно проверяйте журнал регламентных заданий — отправка Telegram должна выполняться без ошибок.
Настройте автоматический запуск массового создания актов, например, 1-го числа каждого месяца (через регламентное задание).
Обучите персонал правилам заполнения заявок: обязательны дата, специалист, договор.
Используйте диаграмму Ганта в графике отпусков для визуального контроля загрузки сотрудников.
При изменении ставки часа по договору — создайте новый договор или измените реквизиты действующего (история изменений не хранится, это повлияет на будущие заявки).
